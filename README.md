# BYTE BACK 방어전 — 2단계 자료를 코드 밖으로 옮깁니다

이 저장소는 1단계의 같은 자료실을 2단계로 바꾼 상태입니다. 가상 메모 4건의 본문은 정적 `data.json`과 브라우저 코드에서 제거하고, 학습용 Supabase 테이블에서 Vercel 서버 함수를 통해 읽습니다. 실제 학생 자료, 토큰, 비밀키를 넣지 마세요.

## 현재 작동하는 기능

- `/` 화면은 `/api/notes`를 호출해 가상 메모 카드 4개를 표시합니다.
- `/data.json`은 빈 `notes` 배열만 가지며 메모 본문을 공개하지 않습니다.
- `api/notes.js`는 Vercel 환경변수에 등록한 Supabase 주소와 서버 전용 비밀값을 서버에서만 읽습니다.
- 서버 전용 비밀값은 브라우저 파일, API 응답, 로그에 넣지 않습니다.
- 2단계에서는 `GET /api/notes` 주소 자체가 아직 공개되어 있어 비로그인 사용자가 자료를 읽을 수 있습니다. 이 약점은 다음 접근통제 단계에서 막아야 합니다.

## Supabase SQL 실행

가상 메모 본문이 들어 있는 1회성 SQL 파일은 GitHub에 커밋하지 않습니다. Supabase Dashboard의 **SQL Editor**에서 제공받은 SQL을 직접 실행합니다.

SQL은 다음 조건으로 테이블을 만듭니다.

- `public.notes`에 `owner_id uuid` 열을 미리 둡니다.
- `owner_id`에 `auth.users` 외래키는 걸지 않습니다.
- RLS를 켭니다.
- `anon`, `authenticated` 역할에는 테이블 읽기/쓰기 권한을 주지 않습니다.
- Vercel 서버 함수가 서버 전용 권한으로 조회하도록 구성합니다.

SQL Editor 실행 후 **Table Editor → notes**에서 `owner_id` 열을 확인하고, 테이블 설정에서 RLS가 **Enabled**인지 확인합니다.

## Vercel 환경변수

Vercel 프로젝트의 **Settings → Environment Variables**에 다음 두 이름을 등록합니다.

- `SUPABASE_URL`
- `SUPABASE_SECRET_KEY`

값 자체는 코드, GitHub, README, 채팅, 로그에 복사하지 않습니다. 등록 후 새 배포를 실행합니다.

## 2단계 확인 절차

1. 배포된 `/`를 열어 카드가 4개 보이는지 확인합니다.
2. 배포 주소 뒤에 `/data.json`을 붙여 열고 빈 `notes` 배열만 있으며 메모 본문이 없는지 확인합니다.
3. 배포 주소 뒤에 `/api/notes`를 붙여 비로그인 상태에서도 자료가 보이는지 확인합니다. **이것이 현재 남아 있는 공개 API 약점입니다.**
4. GitHub 최신 코드에서 **1단계 `data.json`에 있던 네 개의 `content` 문장**을 각각 검색합니다. 최신 파일 검색 결과가 모두 0건인지 기록합니다.
5. 현재 배포의 정적 파일에서도 같은 네 문장을 검색합니다. 개발자 도구 **Sources**와 `/data.json`을 확인하고, 정적 HTML·JavaScript·JSON에 본문이 없어야 합니다.
6. `/api/notes` 응답에는 메모가 남아 있으므로 “자료 접근이 완전히 보호됐다”고 기록하지 않습니다.

## 검색 결과 기록

현재 단계의 목표는 **최신 정적 파일과 최신 GitHub 파일에서 메모 본문을 제거하는 것**입니다. 최신 커밋에서 네 문장이 검색되지 않아도, 1단계의 옛 공개 커밋과 옛 배포가 남아 있으면 과거 노출 자체가 없어진 것은 아닙니다.

기록할 때는 다음처럼 구분합니다.

- 최신 GitHub 파일: 1단계 메모 본문 네 문장의 검색 결과를 기록합니다.
- 현재 배포 정적 파일: 같은 네 문장의 검색 결과를 기록합니다.
- 공개 API: `/api/notes`가 인증 없이 읽히는 현재 약점을 별도로 기록합니다.
- 과거 노출: 옛 공개 커밋이나 옛 배포가 남아 있는 동안 **“과거 노출 해소”라고 쓰지 않습니다.**

## 빌드와 자기 점검

로컬 정적 빌드는 다음 한 줄로 확인합니다.

`npm run build -- --local`

2단계 빌드는 `public/data.json`에 빈 자료만 기록하며, 메모 본문을 다시 복사하지 않습니다. `src/attack-check.mjs`의 2단계 자기 점검은 `/data.json`에서 메모가 제거되었는지와 `/api/notes`가 아직 공개인지 각각 확인합니다. 이 자기 점검은 운영 심판 판정이 아닙니다.
