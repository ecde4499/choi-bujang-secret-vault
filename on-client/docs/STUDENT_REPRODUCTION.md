# 벌레먹은딸기 · 22단계 새 환경 재현 및 릴리스 기록

## 1. 기록 목적과 판정 범위

이 문서는 22단계 「최종 커밋의 새 환경 재현과 릴리스 기록」을 위해 작성한 학생 재현 기록입니다.

- 이 기록은 **학생이 별도 폴더에서 직접 수행한 재현 결과**입니다.

- 현재 릴리스 상태는 **검증 중**입니다. 이 기록만으로 v1.0 또는 운영 인증 완료를 주장하지 않습니다.

### 2.2 커밋 기록 해석

현재 재현 기준은 **과제 제출 화면에 입력하는 40자리 commit SHA**와 공식 `student-source-cli.mjs`로 만든 원문 JSON의 **`commit` 값**이 동일한 제출본입니다.

- 재현 기록의 `현재 제출 commit`은 위 두 값으로 식별합니다.
- 원문 JSON은 프로젝트 밖에서 만들고 `--commit <제출할-40자리-SHA>`를 지정합니다.
- JSON 생성 결과의 `commit` 값과 과제 제출 화면의 commit 값이 다르면 제출하지 않습니다.
- 이전 단계나 이전 제출의 SHA를 현재 재현 기준으로 사용하지 않습니다.
- 이 문서의 단계별 관찰 결과와 미확인 범위는 **현재 제출 commit의 재현 기록**으로 사용합니다.

이 방식은 커밋된 원문만 묶는 공식 원문 전달 도구의 계약과 맞추기 위한 것입니다. 서버 AI가 직접 실행했다고 주장하지 않으며, 학생이 확인한 결과만 기록합니다.

## 5. 데이터 보존·백업·복원 계획

### 5.1 보존 대상

Git으로 보존하는 대상은 **커밋된 소스 코드, 학생 문서, 비밀값이 없는 설정 설명**입니다. 원래 작업 폴더는 재현 과정에서 유지했습니다.

현재 저장소의 `.gitignore`에는 다음과 같은 로컬·민감·생성 항목이 포함됩니다.

```text
artifacts/
bundle-notes.json
.env
.env.*
node_modules/
public/aleph.json
xdr/alerts.log
```

따라서 이 항목들은 새 환경 재현을 위해 기존 폴더에서 무작정 복사하지 않습니다.

### 5.2 백업

- 소스와 학생 문서는 Git 커밋과 원격 저장소를 기준으로 보존합니다.
- 제출 전에는 `git status --short`와 `git rev-parse HEAD`로 작업 트리와 기준 커밋을 확인합니다.
- 비밀값, 인증 파일, 운영 로그는 Git 백업 대상으로 만들지 않습니다.
- 과제의 비공개 원문 전달 JSON이 필요한 경우 과제 화면에서 제공하는 도구를 사용하고 결과 파일은 프로젝트 밖에 둡니다.

### 5.3 복원

소스 복원은 새 빈 폴더에서 저장소를 clone하고 제출 대상 커밋을 checkout하는 방식으로 수행합니다.

```powershell
git clone https://github.com/ecde4499/choi-bujang-secret-vault.git <새-빈-폴더>
cd <새-빈-폴더>
git checkout <제출할-40자리-커밋>
```

그 뒤 `on-client/docs/STUDENT_RUNBOOK.md` 순서로 런타임·문법·실행·브라우저·종료·재실행을 확인합니다.

### 5.4 학생 데이터 백업·복원 범위

현재 `on-client`에서 학생이 작성한 `student/extension.mjs`는 서버가 전달한 값을 화면에 표시하는 역할이며, 학생 코드가 별도 데이터베이스나 백업 파일을 만들지 않습니다. 확인한 제공 브라우저 코드 `public/app.js`에도 `localStorage`, `sessionStorage`, `indexedDB`를 사용하는 학생 데이터 영구 저장 경로가 없습니다.

따라서 이 제출본에서 학생이 직접 보존·복원할 수 있는 것은 다음과 같습니다.

- **보존 가능:** 커밋된 학생 코드, 학생 문서, 비밀값 없는 설정 설명 → Git 커밋/원격 저장소로 백업
- **복원 방법:** 새 빈 폴더에 저장소를 clone하고 제출 HEAD를 checkout한 뒤 `docs/STUDENT_RUNBOOK.md` 절차로 실행
- **별도 복원 대상 없음:** demo 화면 상태와 브라우저의 현재 선택/로딩 상태는 실행 중 상태이며 별도 학생 데이터 백업 파일로 저장하지 않음
- **학생 저장소에서 복원 불가:** 운영 SDP/XDR/AI 계정 상태, 인증 정보, 외부 운영 데이터, 제외된 운영 로그

즉 이 프로젝트의 학생 데이터 보존 계획은 **소스·문서의 Git 백업/복원**이며, 존재하지 않는 학생용 영구 데이터 저장소나 운영 데이터 백업 기능을 있다고 주장하지 않습니다.

### 5.4 보존 한계

- Git에 없는 실제 SDP/XDR/AI 계정 설정과 인증 정보는 이 복원 절차로 복구되지 않습니다.
- `xdr/alerts.log` 같은 제외된 로컬 운영 로그는 Git 복원 대상이 아닙니다.
- demo 예제 자료 재현은 실제 회사/운영 데이터 복원을 뜻하지 않습니다.
- 실제 운영 데이터의 백업·복구 정책은 이 학생 저장소만으로 확인할 수 없으므로 별도 운영 정책이 제공되기 전에는 완료로 주장하지 않습니다.

## 6. 버전과 지원 범위

### 6.1 두 버전 표기의 범위

현재 원문에는 서로 다른 목적의 버전 표기가 있습니다.

- `on-client/package.json`의 패키지/앱 릴리스 버전: **`0.2.11`**
- 제공 서버 `on-client/src/server.mjs`가 API 응답 `meta`에 넣는 `starterVersion`: **`0.1.0`**

`starterVersion: '0.1.0'`은 제공 서버 코드의 응답 메타데이터에 별도로 고정된 값이며, `package.json`의 앱 릴리스 버전 값을 읽어 만든 값이 아닙니다. 따라서 이 재현 기록에서 **프로젝트/앱 버전이라고 할 때는 `package.json`의 `0.2.11`을 뜻합니다.** `starterVersion: 0.1.0`은 API 응답에서 관찰되는 제공 서버 메타데이터 값으로만 기록하며, 이를 앱 릴리스 버전이나 v1.0 완료 여부로 해석하지 않습니다.

제공 서버의 `starterVersion` 값 자체가 무엇을 버전 관리하는지에 대한 별도 계약 설명은 현재 학생 문서에서 확인하지 못했으므로, 그 의미를 임의로 확대하지 않습니다.


| 항목 | 현재 기록 |
|---|---|
| 프로젝트 버전 | `0.2.11` |
| 릴리스 상태 | **검증 중** |
| v1.0 표시 | 하지 않음 |
| 로컬 실행·브라우저·재실행 | 새 환경에서 직접 재현 |
| 13~16 demo 표시 | 예제 자료에서 직접 재현 |
| 실제 Native host/AI 연결 | 미확인 (`NATIVE_HOST_DISABLED`) |
| 실제 AI 사건 설명 | 미확인 |
| 실제 보안 조치 집행 | 미확인 |
| 실제 효과 관측 | 미확인 |
| 실제 설치 패키지 complete/partial OSV 조회 | 미확인 (`PROJECT_NOT_CONFIGURED`) |

22단계 원문 검토를 통과하더라도 이는 **현재 제출 원문의 문서·코드·학생 재현 기록이 서로 일관된다는 수료 판정**이며, 실제 운영 인증이나 v1.0 자동 인증으로 표현하지 않습니다.
