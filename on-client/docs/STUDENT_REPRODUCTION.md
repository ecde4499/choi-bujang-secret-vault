### 2.2 제출 커밋 식별 방식

Git 커밋은 **자기 자신의 SHA를 그 커밋 내부 파일에 미리 기록할 수 없습니다.** 파일 내용이 바뀌면 커밋 SHA도 다시 바뀌기 때문입니다.

따라서 이 문서에서는 22단계 제출 대상을 다음처럼 식별합니다.

- **재현 대상:** 이 `STUDENT_REPRODUCTION.md`를 포함해 과제 화면에 제출하는 **현재 HEAD**
- **40자리 SHA:** 제출 직전에 `git rev-parse HEAD`로 확인해 과제 화면의 커밋 입력란에 기록
- 재현용 새 폴더에서도 같은 HEAD인지 `git rev-parse HEAD`와 `git status --short`로 확인
- 문서만 고친 이전 커밋의 성공 결과를 현재 HEAD의 실행 성공으로 자동 승계하지 않고, 현재 HEAD에서 실행 절차를 다시 수행

이 방식으로 문서의 자기참조 SHA 문제를 피하면서도 서버가 받은 **실제 제출 커밋과 학생 재현 진술을 같은 HEAD 기준으로 대조**할 수 있게 합니다.

## 5. 데이터 보존·백업·복원 계획

### 5.1 보존 대상

Git으로 보존하는 대상은 **커밋된 소스 코드, 학생 문서, 비밀값이 없는 설정 설명**입니다. 원래 작업 폴더는 재현 과정에서 유지했습니다.

현재 저장소의 `.gitignore`에는 다음과 같은 로컬·민감·생성 항목이 포함됩니다.

```text
artifacts/
bundle-notes.json
.env
.env.*
node_modules/
public/aleph.json
xdr/alerts.log
```

따라서 이 항목들은 새 환경 재현을 위해 기존 폴더에서 무작정 복사하지 않습니다.

### 5.2 백업

- 소스와 학생 문서는 Git 커밋과 원격 저장소를 기준으로 보존합니다.
- 제출 전에는 `git status --short`와 `git rev-parse HEAD`로 작업 트리와 기준 커밋을 확인합니다.
- 비밀값, 인증 파일, 운영 로그는 Git 백업 대상으로 만들지 않습니다.
- 과제의 비공개 원문 전달 JSON이 필요한 경우 과제 화면에서 제공하는 도구를 사용하고 결과 파일은 프로젝트 밖에 둡니다.

### 5.3 복원

소스 복원은 새 빈 폴더에서 저장소를 clone하고 제출 대상 커밋을 checkout하는 방식으로 수행합니다.

```powershell
git clone https://github.com/ecde4499/choi-bujang-secret-vault.git <새-빈-폴더>
cd <새-빈-폴더>
git checkout <제출할-40자리-커밋>
```

그 뒤 `on-client/docs/STUDENT_RUNBOOK.md` 순서로 런타임·문법·실행·브라우저·종료·재실행을 확인합니다.

### 5.4 학생 데이터 백업·복원 범위

현재 `on-client`에서 학생이 작성한 `student/extension.mjs`는 서버가 전달한 값을 화면에 표시하는 역할이며, 학생 코드가 별도 데이터베이스나 백업 파일을 만들지 않습니다. 확인한 제공 브라우저 코드 `public/app.js`에도 `localStorage`, `sessionStorage`, `indexedDB`를 사용하는 학생 데이터 영구 저장 경로가 없습니다.

따라서 이 제출본에서 학생이 직접 보존·복원할 수 있는 것은 다음과 같습니다.

- **보존 가능:** 커밋된 학생 코드, 학생 문서, 비밀값 없는 설정 설명 → Git 커밋/원격 저장소로 백업
- **복원 방법:** 새 빈 폴더에 저장소를 clone하고 제출 HEAD를 checkout한 뒤 `docs/STUDENT_RUNBOOK.md` 절차로 실행
- **별도 복원 대상 없음:** demo 화면 상태와 브라우저의 현재 선택/로딩 상태는 실행 중 상태이며 별도 학생 데이터 백업 파일로 저장하지 않음
- **학생 저장소에서 복원 불가:** 운영 SDP/XDR/AI 계정 상태, 인증 정보, 외부 운영 데이터, 제외된 운영 로그

즉 이 프로젝트의 학생 데이터 보존 계획은 **소스·문서의 Git 백업/복원**이며, 존재하지 않는 학생용 영구 데이터 저장소나 운영 데이터 백업 기능을 있다고 주장하지 않습니다.

### 5.4 보존 한계

- Git에 없는 실제 SDP/XDR/AI 계정 설정과 인증 정보는 이 복원 절차로 복구되지 않습니다.
- `xdr/alerts.log` 같은 제외된 로컬 운영 로그는 Git 복원 대상이 아닙니다.
- demo 예제 자료 재현은 실제 회사/운영 데이터 복원을 뜻하지 않습니다.
- 실제 운영 데이터의 백업·복구 정책은 이 학생 저장소만으로 확인할 수 없으므로 별도 운영 정책이 제공되기 전에는 완료로 주장하지 않습니다.

| 실제 설치 패키지 complete/partial OSV 조회 | 미확인 (`PROJECT_NOT_CONFIGURED`) |

22단계 원문 검토를 통과하더라도 이는 **현재 제출 원문의 문서·코드·학생 재현 기록이 서로 일관된다는 수료 판정**이며, 실제 운영 인증이나 v1.0 자동 인증으로 표현하지 않습니다.

## 7. 제출 HEAD 기준 재현 기록

22단계에 제출하는 재현 대상은 **이 문서를 포함하는 현재 제출 HEAD**입니다. 과제 화면에는 제출 직전 `git rev-parse HEAD`로 확인한 실제 40자리 SHA를 입력합니다.

제출 전 새 재현 폴더에서 현재 HEAD를 기준으로 아래 순서를 수행하고, **이 확인 뒤에는 문서나 실행 코드를 다시 커밋하지 않은 채 같은 HEAD를 제출합니다.**

1. `git rev-parse HEAD`로 과제에 제출할 HEAD와 같은 커밋인지 확인합니다.
2. `git status --short`가 빈 출력인지 확인합니다.
3. `Get-Date -Format "yyyy-MM-dd HH:mm:ss K"`로 재현 세션 시각을 확인합니다.
4. `node --version`으로 런타임을 확인합니다.
5. `npm.cmd run check`를 실행해 `student/extension.mjs` 문법 검사를 확인합니다.
6. `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1`로 공식 기본 실행을 확인합니다.
7. 브라우저 `http://127.0.0.1:5189/`가 표시되는지 확인하고 실제 연결 상태를 기록합니다.
8. `Ctrl+C`로 종료하고 같은 실행 명령으로 재실행합니다.
9. `npm.cmd run demo`로 예제 자료를 열고 13~20단계의 표 항목을 다시 확인합니다. demo 결과는 실제 연결 성공으로 기록하지 않습니다.

현재 제출 HEAD에 대해 기록할 관찰 결과는 다음 범위입니다.

- Node.js: `v24.21.0`
- `npm.cmd run check`: 오류 없이 완료
- 공식 기본 실행: 로컬 서버 응답 및 브라우저 주소 안내 확인
- 브라우저: 화면 표시, 기본 상태 **연결 없음**
- 종료·재실행: `Ctrl+C` 종료 뒤 같은 명령으로 재실행 성공
- 실제 SDP/AI 연결 성공: 확인하지 않음
- 실제 AI 사건 설명 성공: 확인하지 않음
- 실제 보안 조치 집행: 확인하지 않음
- 실제 패키지 complete/partial OSV 조회: 확인하지 않음

위 관찰 결과는 **학생이 현재 제출 HEAD를 새 재현 폴더에서 직접 확인한 재현 진술**로만 사용합니다. 서버 AI가 이 명령을 실행했다고 표현하지 않습니다.

서로 다른 코드 커밋의 성공 결과를 합쳐 최종 버전 전체 성공으로 표시하지 않습니다. 제출 HEAD가 바뀌면 위 절차를 그 새 HEAD에서 다시 수행한 뒤 제출합니다.
