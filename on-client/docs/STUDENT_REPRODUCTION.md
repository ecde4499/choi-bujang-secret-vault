## 1. 기록 목적과 판정 범위

이 문서는 22단계 「최종 커밋의 새 환경 재현과 릴리스 기록」을 위해 작성한 학생 재현 기록입니다.

## 5. 데이터 보존·백업·복원 계획

### 5.1 보존 대상

Git으로 보존하는 대상은 **커밋된 소스 코드, 학생 문서, 비밀값이 없는 설정 설명**입니다. 원래 작업 폴더는 재현 과정에서 유지했습니다.

현재 저장소의 `.gitignore`에는 다음과 같은 로컬·민감·생성 항목이 포함됩니다.

```text
artifacts/
bundle-notes.json
.env
.env.*
node_modules/
public/aleph.json
xdr/alerts.log
```

따라서 이 항목들은 새 환경 재현을 위해 기존 폴더에서 무작정 복사하지 않습니다.

### 5.2 백업

- 소스와 학생 문서는 Git 커밋과 원격 저장소를 기준으로 보존합니다.
- 제출 전에는 `git status --short`와 `git rev-parse HEAD`로 작업 트리와 기준 커밋을 확인합니다.
- 비밀값, 인증 파일, 운영 로그는 Git 백업 대상으로 만들지 않습니다.
- 과제의 비공개 원문 전달 JSON이 필요한 경우 과제 화면에서 제공하는 도구를 사용하고 결과 파일은 프로젝트 밖에 둡니다.

### 5.3 복원

소스 복원은 새 빈 폴더에서 저장소를 clone하고 제출 대상 커밋을 checkout하는 방식으로 수행합니다.

```powershell
git clone https://github.com/ecde4499/choi-bujang-secret-vault.git <새-빈-폴더>
cd <새-빈-폴더>
git checkout <제출할-40자리-커밋>
```

그 뒤 `on-client/docs/STUDENT_RUNBOOK.md` 순서로 런타임·문법·실행·브라우저·종료·재실행을 확인합니다.

### 5.4 보존 한계

- Git에 없는 실제 SDP/XDR/AI 계정 설정과 인증 정보는 이 복원 절차로 복구되지 않습니다.
- `xdr/alerts.log` 같은 제외된 로컬 운영 로그는 Git 복원 대상이 아닙니다.
- demo 예제 자료 재현은 실제 회사/운영 데이터 복원을 뜻하지 않습니다.
- 실제 운영 데이터의 백업·복구 정책은 이 학생 저장소만으로 확인할 수 없으므로 별도 운영 정책이 제공되기 전에는 완료로 주장하지 않습니다.

## 7. 커밋 일관성 처리

이번 재현에서 직접 실행한 소스 커밋은 다음입니다.

```text
8462d776e59f04a83db46ac61163129aa3adcf86
```

이 22단계 재현 기록 문서를 추가하면 Git 특성상 새로운 커밋이 생깁니다. 따라서 **재현한 소스 커밋과 재현 기록을 포함한 제출 커밋을 같은 값이라고 허위로 적지 않습니다.**

최종 제출 전에 다음을 다시 확인합니다.

1. 이 문서 추가 이후 `student/extension.mjs`, `src/`, `public/`, 실행 도구 등 실행 코드가 변경되지 않았는지 확인합니다.
2. 제출할 최신 40자리 커밋을 기록합니다.
3. 새 재현 폴더를 그 제출 커밋으로 갱신하거나 새로 clone합니다.

5. 결과가 달라지거나 실행 코드가 수정되면 그 새 커밋을 기준으로 재현 기록을 다시 검토합니다.

서로 다른 코드 커밋의 성공 결과를 합쳐 최종 버전 전체 성공으로 표시하지 않습니다.
