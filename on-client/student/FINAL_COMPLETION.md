# 마지막 총공세 작업 기록

이 문서는 22단계 이후 마무리 작업에서 학생이 고른 핵심 기능, 실제 변경 범위, 아직 확인하지 않은 항목을 구분해 기록합니다.

## 고른 핵심 기능 3가지

1. **업무 앱 접속 판정(ZTNA)**
   - 허용/거부/추가 확인/확인 불가와 요청 실패를 구분합니다.
   - 최종 화면에서는 요약과 다음 행동을 먼저 보여 주고, 기존 판정 이유·시각·원래 상태 코드를 그대로 유지합니다.

2. **보안 기록과 XDR 이상 징후 근거**
   - 접속 기록과 XDR 경보를 구분하고, 기록 상세의 근거·규칙·접속/세션/기기 상태를 확인합니다.
   - 전체 건수와 XDR/접속 기록 건수를 요약하되, 기록이 없다는 사실을 안전하다는 뜻으로 바꾸지 않습니다.

3. **기기·연결·진단 상태**
   - 등록 기기, 현재 연결, 상태 알림, 비밀 없는 진단 정보를 한 흐름으로 확인합니다.
   - 연결 없음·확인 불가·오류는 정상 상태로 바꾸지 않고 다음 행동을 안내합니다.

외부 SaaS 사용량·비용 연결은 이번 최종본의 핵심 기능에서 제외했습니다. 새 비밀키나 외부 계정 연결을 억지로 추가하지 않고 기존 방어전 기능을 완성하는 방향을 선택했습니다.

## 이번에 실제로 바꾼 학생 파일

- `student/extension.mjs`
  - 세 핵심 기능에 `요약 → 다음 행동 → 상세 근거` 순서를 추가했습니다.
  - 기존 13~20단계의 필수 상태 코드, 오류 구분, 필터, 상세 근거, 진단 정보 복사 동작은 제거하지 않았습니다.
- `student/appearance.json`
  - 앱 이름: `BYTE BACK 보안 에이전트`
  - 테마: 남색 포인트 + 밝은 배경/표면
  - 카드 배치: `student-first`
  - 아이콘과 시작 그림은 아직 지정하지 않았습니다.

## 현재 시작 틀 상태

현재 저장소의 `on-client/package.json`은 **0.2.11**입니다.

마지막 총공세의 설치형 앱 포장과 `student/appearance.json` 반영은 **신뢰된 0.2.21 시작 틀 업데이트가 적용된 뒤** 확인해야 합니다. 제공 문서 규칙상 시작 틀 업데이트는 ALEPH/운영 측이 제공한 신뢰된 소스를 사용해야 하며, 다른 학생 저장소의 파일을 대신 복사하지 않습니다.
